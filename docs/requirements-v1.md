# BlockDoc V1 需求基线

状态：需求基线已确认，可用于第一版设计与开发。

## 1. 产品定位

BlockDoc 第一版是一款在用户自己的电脑上启动、通过浏览器访问的单文档块编辑器。

- 初期仅供个人使用，先验证真实编辑体验并逐步修复问题。
- 第一版在本机启动，通过 `localhost` 在 Chrome 或 Edge 中访问。
- 文档数据保存在用户选择的本地文件中，不依赖服务端数据库。
- 编辑器底座采用 BlockNote，并尽量直接使用其原生数据结构、块、菜单和交互。
- 第一版追求尽快形成稳定可用的编辑底座，为后续客户端封装和功能扩展留出空间。

## 2. 第一版范围

### 2.1 启动与单文档模式

- 打开 BlockDoc 后直接进入一个空白新文档。
- 不自动打开上一次编辑的文件。
- 顶部工具栏提供新建、打开、保存、另存为和导出 HTML 等入口。
- 同一时刻只编辑一个文档。
- 第一版不提供多文件标签页和文档库。

### 2.2 文档标题

- 文档标题使用 BlockNote 原生的一级标题块，不设置独立标题字段。
- 新建文档时初始化一个空的一级标题块和一个空段落块。
- 一级标题仍是普通 BlockNote 内容块，用户可以编辑、移动、转换或删除。
- 编辑器不强制文档始终存在一级标题，也不限制一级标题数量。
- 第一个一级标题仅作为默认文件名的来源，不形成额外的数据关系。

### 2.3 源文件格式

- 源文件扩展名为 `.blockdoc.json`。
- 文件内容直接保存 `editor.document` 对应的 BlockNote 原生块数组。
- 文件根节点不增加 `title`、`format`、`version`、`metadata` 等包装字段。
- 打开文件时，将该数组作为 BlockNote 的初始内容加载。
- 保存和加载不得改变合法 BlockNote 块的结构或含义。

示意：

```json
[
  {
    "id": "block-id",
    "type": "heading",
    "props": {
      "level": 1
    },
    "content": [
      {
        "type": "text",
        "text": "建筑系统",
        "styles": {}
      }
    ],
    "children": []
  }
]
```

### 2.4 文件名规则

- 新文档首次保存时，以第一个一级标题的纯文本作为建议文件名。
- 没有可用一级标题时，使用 `未命名文档.blockdoc.json`。
- 首次保存后，修改一级标题不会自动重命名源文件。
- 在文件系统中重命名源文件，也不会修改文档内的一级标题。
- 打开已有文件时，不根据文件名反向修改文档内容。
- 另存为时，重新使用当前第一个一级标题生成建议文件名；用户可以在系统选择器中修改。

## 3. 文件操作

### 3.1 打开文件

- 通过顶部【打开文件】或 `Ctrl+O` 打开 `.blockdoc.json`。
- 浏览器版第一版不提供双击源文件直接关联 BlockDoc 的能力。
- 只接受可解析为 BlockNote 文档块数组的 JSON。
- 文件无效时显示清晰错误信息，并保留当前编辑内容。
- 打开其他文件前，如果当前文档存在未保存内容，应先提供保存、放弃和取消操作。

### 3.2 手动保存

- `Ctrl+S` 执行保存。
- 新文档第一次保存时打开系统保存位置选择器。
- 已获得文件句柄后，保存写回当前 `.blockdoc.json`。
- `Ctrl+Shift+S` 始终执行另存为，并将新文件设为当前文件。

### 3.3 自动保存

- 文档停止变化约 1 秒后触发自动保存。
- 已有文件句柄时，自动保存直接写回当前源文件。
- 顶部显示“未保存”“保存中”“已保存”“保存失败”等状态。
- 保存失败时保留编辑器当前内容，显示原因，并允许用户重试或另存为。

### 3.4 首次保存前的临时草稿

- 新文档尚未选择正式保存位置时，使用 IndexedDB 保存恢复草稿。
- 草稿内容使用当前 BlockNote 文档块数组，并记录最后更新时间。
- 页面重新打开时如检测到草稿，提供恢复草稿和删除草稿操作。
- 首次正式保存成功后清除对应临时草稿。
- 草稿写入失败时明确提示用户进行正式保存。
- IndexedDB 草稿属于浏览器恢复机制，不属于 `.blockdoc.json` 文件格式。

### 3.5 新建与离开保护

- 点击【新建】时，如果当前内容尚未安全保存，提供保存、放弃和取消操作。
- 页面关闭或刷新前，如果最近修改尚未保存或暂存完成，触发离开提示。
- 已成功写入源文件或 IndexedDB 草稿的内容不重复弹出无意义警告。

## 4. 编辑器能力

### 4.1 BlockNote 原生能力

第一版采用所选 BlockNote 版本的官方默认 Schema、默认菜单和默认交互，包括：

- 段落；
- 一级至六级标题；
- 项目符号列表、编号列表、待办列表及默认可折叠列表能力；
- 引用、代码块和分隔线；
- 表格；
- 图片、视频、音频和普通文件块；
- 链接及官方默认文字样式；
- 斜杠菜单、格式工具栏、块侧边菜单、拖拽和缩进等官方默认交互。

除非出现明确缺陷，第一版不改写这些原生能力的行为和数据结构。

### 4.2 撤销与重做

- `Ctrl+Z` 撤销。
- `Ctrl+Y` 重做。
- BlockNote 原生支持的其他等价快捷键可以继续保留。

### 4.3 图片

- 支持通过本地文件选择、剪贴板粘贴和拖拽插入图片。
- 本地图片转换为 Data URL，写入图片块的原生 URL 属性，从而随 `.blockdoc.json` 保存。
- 远程图片在源文件中保留原始 URL。
- 第一版沿用 BlockNote 原生图片标题、预览和尺寸调整能力，不增加自定义图片资源系统。

### 4.4 其他媒体和文件

- 视频、音频和普通文件块沿用 BlockNote 原生 URL 或文件地址。
- 第一版不将视频、音频和普通附件编码进 `.blockdoc.json`。
- URL 对应资源能否离线访问，取决于资源本身的位置。

## 5. 当前文档大纲

- 编辑器右侧显示可收缩的当前文档大纲，形态参考 BlockNote 官网的 “On this page”。
- 大纲来源为当前文档中的一级至六级标题块。
- 按标题级别缩进展示层级。
- 点击大纲项滚动到对应标题块。
- 编辑器滚动时高亮当前所在章节。
- 大纲默认展开，并在浏览器中记住展开或收缩状态。
- 没有标题时显示简洁空状态。
- 大纲通过 BlockNote 文档数据、块 ID 和编辑器事件生成，不创建自定义目录块，也不写入源文件。

## 6. 文档内块链接

- 每个内容块可从原生拖拽手柄菜单复制当前文档内的块链接。
- 点击内部链接直接跳转并短暂高亮目标块，悬停链接可编辑或删除。
- 块链接支持直接粘贴为链接、粘贴到已选文字，以及通过原生超链接输入框添加。
- 块移动后链接继续有效；目标块被删除时显示失效提示。
- 导出的单文件 HTML 保留块内跳转。

## 7. HTML 导出

- 顶部提供【导出 HTML】操作。
- 导出结果为一个可直接分发和打开的 `.html` 文件。
- 默认文件名与当前源文件同名，仅将 `.blockdoc.json` 替换为 `.html`。
- 未保存文档使用第一个一级标题生成默认文件名；无标题时使用 `未命名文档.html`。
- 导出内容包含完整文档、必要样式和本地内嵌图片。
- HTML 以静态阅读为目标，不承载 BlockDoc 编辑和保存能力。
- 本地图片以 Data URL 继续内嵌。
- 对远程图片，导出时尝试获取资源并转为 Data URL，且不修改源文档中的 URL。
- 远程图片受跨域、鉴权或网络状态影响而无法内嵌时，保留原 URL，并在导出完成后提示哪些资源仍依赖网络。
- 视频、音频和普通文件块保留其原始 URL，因此这些资源可能仍需要网络。

## 8. 界面与布局

- 界面语言使用简体中文。
- 第一版使用浅色主题。
- 编辑区使用 BlockNote 默认内容宽度。
- 页面由顶部工具栏、中央编辑区和右侧大纲组成。
- 不增加独立标题输入框。
- 工具栏保持紧凑，以文件操作和保存状态为主。

## 9. 浏览器与本地运行

- 第一版目标浏览器为最新版 Chrome 和 Edge。
- 应用在用户自己的电脑上启动，通过本地地址访问。
- 文件访问使用浏览器提供的文件选择器和文件句柄能力。
- 第一版不要求部署公网网址，也不要求安装为 PWA。
- 应用运行期间不依赖后端服务保存文档。

## 10. 第一版明确不做

- 多文件标签页；
- 文档库、文件树和最近文档管理；
- 双击 `.blockdoc.json` 后由操作系统直接启动 BlockDoc；
- 标题与文件名持续双向同步；
- 独立标题字段和自定义文档包装格式；
- Scrollytelling；
- 多栏块；
- AI 功能；
- 评论、协作和多人实时编辑；
- 自定义页面宽度档位；
- 视频、音频和普通附件内嵌到源文件；
- 桌面客户端封装。

## 11. 工程约束

- 锁定 BlockNote 及相关依赖的具体版本，升级前验证已有 `.blockdoc.json` 的兼容性。
- 尽量通过 BlockNote 公共 API 和官方组件实现功能，不修改 BlockNote 包源码。
- 应用层功能不得向原生块数据写入 BlockDoc 专用字段。
- 文件写入采用完整 JSON 生成和原子化程度尽可能高的写入流程，避免产生半截文件。
- 自动保存、草稿保存和 HTML 导出失败必须可见，不允许静默失败。
- 第一版优先保持实现直接，避免为延期功能预建复杂抽象。
- `files/BlockDoc功能验收示例.blockdoc.json` 作为持续维护的功能验收基准；新增可在文档中体现的功能时，同步补充对应内容和自动校验。

## 12. 核心验收场景

1. 启动本地应用后，浏览器显示包含空一级标题和空段落的新文档。
2. 编辑内容后，未首次保存的文档可在刷新页面后从 IndexedDB 恢复。
3. 首次按 `Ctrl+S` 能选择路径并创建 `.blockdoc.json`。
4. 源文件根节点是 BlockNote 原生块数组，可重新打开并恢复全部支持的块内容。
5. 首次保存后继续编辑，约 1 秒内自动写回当前文件并更新保存状态。
6. 修改第一个一级标题不会重命名已保存文件。
7. 粘贴或拖入本地图片后，重新打开源文件仍能显示该图片。
8. 右侧大纲随标题增删实时更新，支持点击跳转和滚动高亮。
9. 内容块菜单可复制块链接，三种链接创建方式均可在当前文档内跳转并高亮目标。
10. 导出的 HTML 是单个文件，本地图片、样式和块内跳转无需额外资源即可使用。
11. 打开无效 JSON 时，当前文档不丢失并收到明确错误提示。

## 13. 后续阶段候选

- 桌面客户端和操作系统文件关联；
- 多文件标签页与文档库；
- 标题与文件名同步重命名；
- Scrollytelling；
- 可选页面宽度；
- 主题切换；
- 更完整的附件打包；
- 发布、分享与多人使用能力。
