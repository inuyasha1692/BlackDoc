# AI 修改打开的文档

每个文档窗口默认提供本地 AI 连接，无需手动启用。运行下面的 `list` 命令可发现连接目录和文档路径，再使用 `read` 读取当前文档。未收到读取或修改请求时，连接目录只保存连接信息，不生成完整正文快照。

连接使用每个文档会话独立的随机凭证，脚本自动携带凭证执行读取和修改。凭证保存在本机连接目录中，这属于同一用户下的本地工具访问机制；能读取该目录的程序也能取得凭证。不要将连接目录或凭证提供给不可信工具。

关闭窗口或切换文档后，旧连接目录会清理。异常退出后可能留下文件，下次启动时会清理已失效的目录，并保留仍在使用的连接。AI 读取后的响应包含完整正文及内嵌资源，保存在临时连接目录中，随连接清理。

在仓库目录运行（将路径替换为 `list` 返回的实际连接目录）：

```powershell
node scripts/ai-document.mjs list
node scripts/ai-document.mjs "C:\...\blackdoc-ai\..." read
node scripts/ai-document.mjs "C:\...\blackdoc-ai\..." apply "request.json"
```

`list` 列出连接目录与文档路径。使用【功能示例】打开的是未绑定仓库文件的文档副本；修改仓库里的示例文件不会刷新该副本。要修改当前窗口，AI 必须通过连接脚本的 `read` 读取当前文档，再通过 `apply` 提交。

`read` 返回当前编辑器的 `revision`、`path` 和完整 `blocks`。`apply` 的输入是 JSON 对象，包含读取时的 `revision` 和修改后的完整 `blocks` 数组。保留已有块的 ID；新增块使用新的唯一 ID。未修改的块、图片数据和画布数据应完整保留。可调整正文、标题、表格、插入或删除块。

修改会显示在编辑器中，作为一次可撤销操作，并触发现有自动保存。成功响应表示已应用到编辑器，磁盘保存状态以应用顶部提示为准。未保存的文档继续暂存为草稿。

如果读取后正文发生变化，修改会被拒绝；重新读取、合并最新内容后再提交。请求超时后先检查当前正文和 `response.json`，确认是否已应用，再决定是否重试。不要直接改写正在打开的 `.bdoc` 文件。

给 Codex 的示例请求：

> 使用本仓库的 scripts/ai-document.mjs，先通过 list 找到当前文档的连接目录。读取当前文档，将第二节整理成表格。保留其他内容和已有块 ID，提交带读取版本号的修改，然后检查响应。
